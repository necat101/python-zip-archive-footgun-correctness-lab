# python-zip-archive-footgun-correctness-lab

A small, reproducible, Python-stdlib-only correctness and safety lab about ZIP archive footguns.

Inspired by a Hacker News thread: https://news.ycombinator.com/item?id=37897444  
Linked rant: https://games.greggman.com/game/zip-rant/

## What HN users were debating

ZIP is widely useful and almost universally supported – but the format has quirks that catch people off guard if they assume archives are "just files in a folder."

**Central directory vs local headers.** ZIP stores a central-directory index at the end of the archive. Local file headers appear before each file's data. The two can disagree – especially after appending, replacing, or deleting entries. Correct readers scan from the end, find the EOCD record, and trust the central directory – not stray local headers.

**Why ZIP is indexed, tar is stream-shaped.** Tar has no index – you read header, skip, header, skip, until you find what you want. ZIP's central directory means you can list contents and extract individual files without reading the whole archive. That's why ZIP works as a container format (OOXML, JAR, EPUB, Wheels) while tar.gz is "unpack everything."

**Duplicate names are a policy decision.** The ZIP spec doesn't forbid duplicate filenames in the central directory. What should an extractor do? First entry? Last entry? Error? That's a policy choice – not a universal truth you can derive from the format.

**Safe extraction needs path containment checks.** Blindly joining `dest_dir + member_name` is unsafe. Archive entries can contain:
- `../` path traversal
- Leading `/` absolute paths
- Windows drive paths like `C:/temp/file.txt`
- Backslash separators (literal in ZIP, path separators on Windows)
- Mixed `a/../../b` traversal

A safe extractor must normalize paths and verify the resolved target stays inside the destination directory.

**Compression ratio and size guards.** A tiny compressed file can expand to huge uncompressed sizes (zip-bomb caveat). Declared uncompressed size, compression ratio, and member count should all be bounded before extracting.

**CRC is useful, not a security model.** CRC-32 catches transmission corruption, not malicious tampering. Still: validate CRCs, don't silently ignore read errors.

**Symlinks and platform attributes are caveats.** External attributes can encode Unix permissions, symlink flags, etc. Don't blindly follow them.

**This lab is not a production archive scanner.** It's a tiny toy lab to make the HN debate concrete and testable. No malware, no real zip bombs, no external tools.

## Cases

40 deterministic toy archives, generated by `generate_cases.py` using Python stdlib `zipfile` only:

- normal files, nested directories, empty directory entries, multiple files
- stored vs deflated compression, archive comments
- Unicode filenames, spaces/punctuation
- backslash vs forward-slash path separators
- absolute paths (`/etc/passwd`), `../` traversal, `../../` traversal
- Windows drive paths (`C:/temp/file.txt`), backslash traversal
- duplicate filenames (2× and 3× repeats)
- CRC mismatch, malformed non-ZIP
- prefix bytes before ZIP, suffix junk after ZIP, concatenated ZIPs
- toy compression-ratio bomb caveat (50 KB zeros → ~180 bytes)
- file count guard (40 files), total uncompressed size guard (80 KB)
- symlink-like external_attr, executable-looking filenames
- extension-trust caveats (`invoice.pdf`, `document.txt.exe`)
- `./` prefix, double slashes, dotfiles, empty files

All archives are tiny, fake, deterministic, generated in-repo. No downloads, no real user files, no malware.

## Methods

1. **zipfile_infolist_baseline** – inspect central-directory metadata via `ZipFile.infolist()`
2. **zipfile_read_crc_baseline** – read all members, forcing CRC/error handling
3. **safe_member_path_validator** – pathlib-style normalization + destination containment check
4. **safe_extract_to_tempdir_baseline** – extract only path-safe members into `tempfile.TemporaryDirectory()`
5. **duplicate_name_detector** – detect repeated member names in central directory
6. **compression_ratio_guard** – flag `uncompressed / compressed > 100`
7. **total_size_and_count_guard** – reject `uncompressed > 60KB` or `members > 30`
8. **prefix_suffix_zip_reader** – document Python zipfile's prefix/suffix acceptance
9. **naive_path_join_extractor_dry_run** – intentionally unsafe `os.path.join(dest, name)` baseline, dry-run only, expected to fail traversal cases
10. **naive_extension_trust_baseline** – intentionally weak extension-trust baseline, expected to miss path/code risks

No external tools. No `7z`, `unzip`, `libarchive`, `tar`, `binwalk`, or security scanners. Python stdlib only.

## Running

```bash
python3 -m py_compile generate_cases.py run_lab.py
python3 generate_cases.py
python3 run_lab.py
```

Results go to `RESULTS.md`.

## Results

See [RESULTS.md](RESULTS.md).

Summary (Python 3.12.3, Linux):
- 40 cases × 10 methods = 400 runs
- Pass: 400, Fail: 0
- 8 unsafe-path cases, 2 duplicate-name cases, 2 CRC-error cases, 1 malformed case
- 10 naive-negative cases (naive methods expected to fail)

## Safety rules

- All archives generated deterministically by the repo itself
- No real malware, no real user files, no downloaded archives
- Extraction tests only happen in `tempfile.TemporaryDirectory()`
- Dangerous paths are validated/dry-run, never extracted to repo or system
- Compressed/uncompressed sizes are tiny and bounded
- No network calls, no external tools, no package managers
- This is a toy lab, not a security scanner
